## Введение

Настоящее техническое задание распространяется на разработку, испытание и оформление результатов практики по созданию программного продукта **«Aegis»** — информационной системы в виде **веб-приложения** (кроссплатформенный интерфейс в браузере, адаптивная вёрстка), предназначенной для **регистрации пользователей, обмена личными сообщениями, публикации записей в ленте, работы с вложениями** и **организации аудио- и видеозвонков** (сигналинг через сервер, медиа — по WebRTC).

Продукт реализуется в архитектуре **клиент — сервер**:

- **Клиент:** SPA на React, сборка Vite, PWA-ориентированные возможности; часть логики шифрования и ключей выполняется в браузере (end-to-end для полезной нагрузки сообщений).
- **Сервер:** Node.js (Express), **Socket.IO** для оперативных событий (сообщения, статусы, сигналинг звонков), **Prisma ORM**, СУБД **PostgreSQL**, REST API для аутентификации, профилей, чатов и загрузки файлов.

Целевыми пользователями на этапе практики являются **демонстрационные сценарии** (обучающий проект и отчёт по практике); внедрение в промышленную эксплуатацию не является обязательным результатом ТЗ.

## 3. Требования к программному изделию

### 3.1. Требования к функциональным характеристикам

Разработка должна обеспечивать выполнение следующих функций (в объёме, реализованном в репозитории на момент защиты практики):

1. **Аутентификация и сессия**
   - регистрация пользователя (учётные данные, при наличии требований курса — публикация публичного ключа для E2EE);
   - вход по логину/паролю;
   - выдача access- и refresh-токенов, обновление сессии;
   - выход из системы (инвалидация refresh на сервере при необходимости).

2. **Профиль и пользовательские данные**
   - просмотр и изменение данных профиля (в границах реализованного API);
   - загрузка и отображение аватара и др. медиа, предусмотренных интерфейсом.

3. **Чаты и сообщения**
   - список диалогов / чатов (в соответствии с моделью данных Prisma: личные и групповые чаты — по реализации);
   - отправка и получение сообщений; на стороне сервера хранение **метаданных и шифротекста** (содержание не расшифровывается сервером при E2EE);
   - отображение статусов доставки/прочтения (при наличии в API);
   - вложения (изображения, файлы, голосовые/видео-заметки по UI), загрузка на сервер с последующей выдачей **авторизованным** пользователям.

4. **Лента и смежный функционал (клиент)**
   - просмотр ленты записей, комментарии, навигация по разделам, предусмотренным клиентским приложением (в объёме учебного проекта).

5. **Real-time**
   - подключение к **Socket.IO** с передачей JWT;
   - события: новые сообщения, индикаторы набора текста, обновление присутствия (presence), иные события из общего контракта `SOCKET_EVENTS` (пакет `@aegis/shared`).

6. **Звонки (WebRTC)**
   - инициация **аудио-** и **видеозвонка** в рамках **прямого (DIRECT) чата с двумя участниками**;
   - сигналинг (invite, accept, reject, SDP, ICE) через Socket.IO;
   - получение медиапотоков в браузере (getUserMedia), установление **RTCPeerConnection**, обмен кандидатами ICE (STUN; при необходимости в отчёте отметить ограничения без TURN).

7. **Безопасность и ограничение доступа**
   - middleware аутентификации для защищённых маршрутов API;
   - базовые меры: CORS с учётом origin фронта, ограничение частоты запросов (rate limit), заголовки **Helmet** на стороне Express;
   - в production — обязательный **JWT_SECRET**, настройка **trust proxy** при работе за reverse-proxy.

**Исходные данные** для работы системы: учётные записи пользователей, идентификаторы чатов и сообщений, файлы вложений, параметры окружения (переменные `.env`), строка подключения к PostgreSQL.

**Результаты работы** для пользователя: авторизованная сессия, актуальная переписка и лента, файлы вложений, стабильное real-time взаимодействие, успешное установление звонка при соблюдении условий сети и браузера.

### 3.2. Требования к надёжности

- устойчивость к кратковременным сбоям соединения (повторное подключение Socket.IO на клиенте);
- **не допускать** хранение паролей в открытом виде (хеширование, например bcrypt);
- предусмотреть **корректное завершение** сессий звонка и сокетов при обрыве связи;
- для демонстрации на практике — **резервное копирование** исходного кода и базы (на усмотрение: `pg_dump`, копия репозитория), регламент фиксируется в отчёте.

Требования уровня «восстановление не более 30 минут» / «ИБП для всех рабочих мест» из шаблонного ТЗ для склада **не являются обязательными** для учебного стенда; при переносе на предприятие они обсуждаются отдельно.

### 3.3. Условия эксплуатации

- **Клиент:** современный браузер (Chromium / Firefox / Safari актуальных версий), разрешение экрана от мобильного до десктопа (адаптивный UI).
- Для **криптографии в браузере** и **медиа** требуется **защищённый контекст** (HTTPS или localhost).
- Пользователь должен уметь пользоваться браузером и пройти простую регистрацию/вход.
- Администрирование учебного стенда: установка **Node.js**, **pnpm**, при использовании БД в Docker — **Docker Desktop**; настройка переменных `DATABASE_URL`, `JWT_SECRET`, `CLIENT_ORIGIN` и портов.

### 3.4. Требования к составу и параметрам технических средств

**Минимальная конфигурация рабочего места разработчика и демонстрации:**

- Процессор: **4 логических ядра**, архитектура x64 или ARM64.
- ОЗУ: **8 ГБ** (рекомендуется 16 ГБ при одновременной работе IDE, браузера, Docker и сборки).
- Диск: **20 ГБ** свободного места (проект, `node_modules`, образы Docker, данные PostgreSQL).
- Сеть: доступ в Интернет для установки зависимостей (при очном показе — достаточно локальной сети для клиент–сервер).

**Серверная часть в учебной конфигурации:**

- **PostgreSQL** (локально или в контейнере, порт согласовать с `DATABASE_URL`, в т. ч. нестандартный порт хоста при конфликте с установленным экземпляром СУБД).
- Процесс **Node.js** для API и Socket.IO (порт задаётся через `PORT`, по умолчанию 3000).
- Для медиафайлов — каталог на диске (`UPLOAD_DIR` / вложенные каталоги приложения).

Конфигурации уровня **Intel Xeon, RAID, ТСД для склада** из исходного шаблона **не требуются** для объёма настоящего ТЗ.

### 3.5. Требования к информационной и программной совместимости

- **СУБД:** PostgreSQL, версия совместимая с используемым **Prisma** (в проекте — схема `prisma/schema.prisma`, миграции в `prisma/migrations`).
- **Серверная платформа:** Node.js с поддержкой ES Modules, **TypeScript** при сборке.
- **Клиент:** **React**, сборщик **Vite**, стили **Tailwind CSS** (по факту репозитория).
- **Связь клиент-сервер:** REST (JSON), WebSocket поверх HTTP (Socket.IO), единый базовый префикс API из пакета `@aegis/shared`.
- **Совместимость ОС разработки:** **Windows 10/11**, **Linux**, **macOS** — при наличии Node, pnpm и браузера.
